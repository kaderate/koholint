# Roadmap — what remains

Only what is left to do. When something lands, delete it here (git is the history). Amend freely.

**Goal:** an agent plays Link's Awakening DX through the engine. Shield is done and reliable; the sword is next.

## Next, in order
Design and decisions of 2026-10-24: `docs/superpowers/specs/2026-10-24-screen-protocol-and-improvement-loop-design.md`.
1. **Inventory and shield.** Inventory in the context, `use_item`, `guard`, `item_gained` events by inventory diff (also gives the sword milestone); measure how the shield blocks.
2. **Enemies.** Census with a hostile entity (kind `enemy` never measured), then avoidance in the planner and explore; no fighting before the sword.
3. **Improvement loop, levels 1-2.** Symptom detectors (not ready, partial maps, NPC not exhausted, sign unread, damage, unused item, repeated failure, cost drift) filling `summary.json` `symptoms` and `suggestions.md` with frames shown in the timeline; then an offline analyst agent writing proposals for the owner (`koholint analyze <run>`). Level 3 (patch in a worktree, tests, keyframe-forked A/B) later. Agent may write more data, never code.
4. **Map screen as an objective source.** The manual says the map shows "!?" marks (important places) and "message" marks (where an important message was heard): read them deterministically. The map cursor address is unknown.
5. **Perception gaps.** Sword milestone (via inventory diff or RAM), Link's capabilities, deterministic dialogue text decoding from VRAM (dialogue is read as an image, then stitched), `notable` events (so `last_notable` stops being empty), kind `object` of entities.
6. **Lead statuses.** Leads are only open claims: add open/tested/refuted with evidence; measure whether goal, leads and people's memory give a progress signal.
7. **Game over and save in the loop.** The screens and `choose_option` are measured; integrate "continue" after death and a `save_game` skill (needs the boot script to resume from the title after quitting and a check that the cartridge RAM changed; the four-button combination is not reachable through `press`).
8. **Finer navigation (plan 4b), interactions beyond walking, combat.** Tile lattice and tile-level beliefs, exits straddling two cells; push, dive/swim, item use; combat with a deterministic baseline first, Jev only afterwards (`docs/runs/2026-10-jev-spike.md`: 18 % agreement vs 21 % random on explore direction, but 0.00003 USD and 0.2 s per call).
9. **Viewer and live control.** Fork from the UI, pause/stop of the live engine; an optional `--live-clock` with pause-on-danger and a reflex layer (the emulator stays paused between decisions today). Background music (comfort, low priority): the viewer embeds the YouTube IFrame player (button, off by default because of browser autoplay rules) and switches track with a fade by place kind or room through a data file (e.g. `data/music.json`, track order of the playlist to be given by the owner); follows the frame in replay; not the emulated APU (the engine advances in bursts and pauses during agent calls, so live audio would be choppy; emulated sound would only work in replay).

## Open decisions and loose ends
- Addresses at `verified_count: 1` need a second independent check (`name_length`, `max_hearts`, `dialog_state`); `entity_state` (0xC290) meaning is unknown.
- Ladder beyond shield and sword; whether a run may inherit a map, a goal or leads from a previous run.
- **talk_to.** The entity box is assumed 16x16 pixels centred on its position, which holds for the people measured (type 62 at (80,56) covers 4 cells of the starting house; a talk_to aimed at any of 3 of them talks to her); measured in run `20261101-122743-1fec` (24 of 36 talk_to stopped `target_free`): 15 on type 111, which walks off its cell during the walk and does not block Link (A opened facing it from up to 19 px), 8 on creatures of kind `unknown` (types 108, 110) that the agent took for people, 1 on type 115 where A fell in the 24-frame post-dialogue cooldown and the retarget kept the walk's stale stop reason; replayed on 14 of those states the new talk_to talked in 12 (one `blocked`, one cut by the replay limit). Two people overlapping in front of Link make the reported speaker a guess; a person who keeps walking away after 6 re-plans still ends `target_free`; type 111 standing at the screen edge (x 6 in 179/0) gave no response from 3 sides in run `20261101-140253-3cc4`.
- **People and dialogues.** A text is attributed to the entity `talk_to` faced when the dialogue opened, else to the last successful `talk_to` target cell (a text that opens by itself is not attributed); two people of the same entity type in a place share one memory; a dialogue longer than the page limit counts as several talks; the world stamp (milestone, places visited) misses other changes such as items; `new_text` and people's memory compare letters and digits only; stitching joins on an overlap of 7+ characters that starts on a word and may end mid-word, so a real repeated phrase of that length across two pages is merged once; the conversation signature (sorted full text pixel rows of the box, found as rows filled at 90 % with the darkest DMG shade) is not checked in dark rooms or with a yes/no box; type 117 `npc` is verified once, types 45 and 108-110 stay `unknown`; sprites without an entity (3 outdoors in 161/0) are unexplained.
- **Revisit and arrival engagement.** After a sheet reading during a revisit the model's skill choice is replaced; the 1800-frame cycle, 6-round, 4-engagement and 900-frame per-visit caps are unmeasured; engagements are hidden from the explore autopilot (its last explore stop stands); a sign is read once per run (its text is assumed fixed); only verified signs are engaged, and furniture (153/154) is never engaged.
- **Object census.** 62 places scanned (60 of map 0, 2 houses): signs are object 212 (4 rooms) and 94 (1 room), read facing up only; a sign whose cell below is not standable in the probe stays unmeasured (225/0); caves, dungeons and other maps are not scanned; Link is placed by a RAM write in the probe, so a cell he could not reach by walking still counts.
- **Place cards.** Exits are border cells believed walkable, not exits taken; a card is written per visit, not refreshed when entities move or appear later in the visit.
- **Doors.** Door ids are measured on map 0 only (226 at 5 house doors, verified; 225 at one door, hypothesis); doors entered from another side than below, stairs, cave mouths and dungeon entrances are not measured; a door whose cell below is not reachable is never tried.
- **Leads.** Sheets are attached only to `choose_skill`, so an objective chosen right after a dialogue cannot cite its leads yet; a failed sheet call loses the dialogue pages (PNGs remain under `prompts/`).
- **Explore autopilot and candidates.** A/B of flow-16 (`docs/runs/2026-11-arrival-protocol-lot-b.md`): cost per 1000 frames 0.434 of `off`, places 1.32x, 3 forks per arm from one frame; the caps (6 explores, 2400 frames) are unmeasured. An autopilot explore after a new place skips the model's first look at that place, and a harness-picked `new_place` objective skips its `choose_objective` (only the arrival engagement runs first). Candidates: remote people and signs come from the last place card of each place and are listed only when a route over explore's exits is known; a door Link stands on or just below counts as the one he came out of; a target `talk_to` is tried once; `talk_to` talked in 10 of 21 attempts per arm in the A/B (12 of 15 in the live run), a sign of 146/0 gave no response 3 times; place names are free text and a lead's `where` resolves only by exact name or id.
- **Explore.** Live checks: runs `20261101-134255-8c41` (flow-15 first cut: 178/0 and 179/0 sent explore to each other 38 times, each for exits it could not reach, fixed by `pending`) and `20261101-140253-3cc4` (28 places in 105 changes, 5 buildings entered, but 17 re-entries of 161/14 from 147/0 because Link comes out standing on the door and a frontier step up re-entered; fixed by the door rules and the autopilot return guard, not yet confirmed live: run `20261101-141755-eca1` stopped on agent failures after 7445 frames). A side left once counts as tried from every cell of that side (one neighbour per side, as on the overworld grid; a side split by a wall into two areas leads to one of them only); the world route follows only exits explore itself took, and a place reached but never surveyed counts as untried; walls and tried exits are permanent per place; border exits are tried blindly (no passability or static-sprite check) and a dead border cell costs two paid calls; an exit whose step opens a dialogue by itself is skipped silently; the `untried_object` range (3 cells) and the leg/outward frame limits are unmeasured; its memory is outside the beliefs.
- **Readiness.** The play `ready` list is a blocklist (`link_motion_state` 2, 3, 4): unmeasured motion states (hole fall, revolving door, swimming, stairs) fail open. `loading` (mode 11, submode not 7) is gated as not ready: the 5 loadings of run `20261024-184627-b97e` (submodes 0-6, 27-30 frames) and the intro loading of a gated run ended with no input; other loading paths (warps, dungeon doors) are unchecked. Measured on the overworld and house doors only (runs `20261024-184627-b97e`, `20261024-095541-18df`): screen changes in caves and dungeons, holes, swimming, stairs, conveyor or scripted pushes and `link_motion_state` values other than 0, 2, 3, 4 and 7 are not measured (an unknown value counts as ready); `transition_direction` and the candidate 0xC129 are recorded but unused; a decision taken one frame before a scroll starts (Link walking into the edge) is not caught; the 600-frame stuck limit is a guess. `terrain_hash` includes animated tile pixels (4 phases of about 21 frames in places with water or flowers), so `screen` events re-emit on animation and a first screen "differs" from the next one even when ready (18 of 33 visits; 0 of 33 by BG tile indices).
- **Game modes.** Modes 1, 4, 5, 8, 9, 10 and above 12 (credits, file copy and delete, other scripted scenes) are not in `data/modes.json` and surface as `unknown_mode`; yes/no choices inside a text box are not modelled; the game ignores START and SELECT about 12 frames after returning to play and a SELECT shorter than 4 frames (windows unmeasured).
- **Place kinds.** Only map 0 (overworld) and map 16 (houses) are observed; caves and dungeons need a probe of their `map_id` values (they show as `other`).
- **Viewer.** Host-header check on GET routes (only `POST`s check it); per-macro fsync cost on long runs; `verify` replays from boot (use keyframes).
- **Run storage.** `places_seen` counts perceived places only.
- **Agent loop.** `resume` without `--agent` on an agent run silently continues with WalkAndTalk; timed-out or cancelled client calls count as $0; the claude subprocess inherits HOME (accepted); `Run#fork` copies decision events with `prompt_sha` but not their prompt files, and forks a parent of an older flow into the current one (its trace prefix is assumed compatible); the `objective started` event precedes the `decision` that chose it; automatic dialogue pages flush only on `choose_skill` tours; the interaction log attributes a talk_to to the object at (or within one cell of) its target, so NPCs that move can read as never tried.
- **Vision deferred.** Sprite flips are not in the sprite pattern; sprites at y 1..8 in 8x8 mode and sprite height hardcoded to 16 (carry LCDC bit 2); tile bytes not memoised per snapshot; BG-disable not handled; `World#add_screen` assumes event order; probe `moved` ignores `hp_delta`; the misaligned memo is keyed by pixel; the 32-frame hold margin is unmeasured; no free-Link rule at one-way ledges; policies receive the live `Beliefs`; the contradiction check ignores knockback; weak `--grid` CLI and colour-map tests; `Engine.resume` re-emits one `screen` event.
- **Parked code smells.** `GRID_ROWS`/`GRID_COLS` duplicate `Geometry`; `goto` settle duplicates the perpendicular centring logic; `Ledger` doubtful cells are recomputed per direction; `pick`/`place_of` are public class methods; a 170-char line in `agents/context.rb`; ROM goto/walk tests hardcode distances; step results never carry `blocked_at` by decision.
- Test runner: rspec vs minitest (not decided); the suite takes about 5 minutes (a cold emulator cache in a new worktree is the main cost; the cache is now shared in the main checkout's `tmp/emulator_cache`, `delegated_policy_test` still takes ~170 s when warm).
